# Soundry

개인 컴퓨터에서 음악을 만들고 듣고 비교하며, 프로젝트별로 관리하는 로컬 AI Music Studio입니다.

기본 생성 경로는 **Codex CLI 작곡 → 로컬 악기 합성 → WAV 저장**입니다. 프로젝트·생성 이력·플레이어·음원 관리·즐겨찾기 보관함을 함께 제공합니다. 유료 음악 API나 Fal 키는 사용하지 않습니다.

Codex CLI가 프롬프트를 바탕으로 화성·멜로디·리듬·곡 구성을 JSON 악보로 작성하고, Soundry가 자체 악기로 stereo WAV를 만듭니다. 연주곡 전용이며 기본 길이는 150초, 선택 범위는 90–180초입니다. 기존 ChatGPT 로그인과 계정 사용 한도가 적용됩니다. CLI의 AI 추론에는 텍스트 전송이 있으며, 음원 합성·저장은 이 컴퓨터에서 처리합니다.

CLI 전환은 실제 150초 곡의 생성·저장·화면 재생·탐색·원본 다운로드까지 검증했습니다. 자동 QA 433개가 통과했습니다. 요청한 테스트 음원 20곡의 제작 현황은 별도 제작 계획에서 실제 파일을 기준으로 집계합니다. [출시 체크리스트](docs/quality/release-checklist.md)에 근거를 기록합니다.

## 설치와 실행

앱 실행에는 Node.js 24 LTS(24.12 이상, 25 미만)와 npm 11이 필요합니다. 전체 QA에는 Python 3.10 이상과 Git도 사용합니다. 저장소 루트에서 고정된 lockfile로 설치합니다.

```sh
npm ci
```

Codex CLI가 설치되어 있고 ChatGPT 계정으로 로그인되어 있어야 실제 작곡을 사용할 수 있습니다. API 키 인증은 사용하지 않습니다. CLI가 없거나 로그인이 필요해도 기존 프로젝트·음원은 열 수 있고, 새 생성은 준비 안내와 함께 제한됩니다.

시작 전에 포트나 저장 위치를 바꾸려면 `.env.example`을 참고해 `.env`를 설정합니다. `.env`가 없을 때만 예제 파일을 복사하고, 기존 설정은 유지합니다. 기본 UI 포트는 5173입니다. 다른 앱이 5173을 사용 중이면 다음 값을 지정합니다. 이 기기의 화면 검증에는 5174를 사용했습니다.

```dotenv
UI_PORT=5174
```

```sh
npm run dev
```

- 기본 설정: [Soundry 열기 — 5173](http://127.0.0.1:5173)
- `UI_PORT=5174` 설정: [Soundry 열기 — 5174](http://127.0.0.1:5174)

터미널에 표시된 주소와 설정한 포트를 사용합니다. API는 `http://127.0.0.1:3000/api`이며 3000은 고정입니다. UI와 API는 이 컴퓨터의 loopback에만 연결됩니다. 사용 중인 포트에서 자동으로 다른 포트로 이동하지 않습니다. **Ctrl-C**로 화면 서버와 API 서버를 함께 종료합니다.

## 처음 사용하기

1. **새 프로젝트**를 만들고 작업 공간을 엽니다.
2. 장르 예문을 고르거나 음악 아이디어를 직접 작성하고 곡 수를 선택합니다. 현재 공급자가 지원하지 않는 설정은 비활성화됩니다.
3. 생성 버튼을 누릅니다. CLI가 곡을 작곡하고 로컬 렌더러가 WAV를 만듭니다. 접수 후에는 다른 화면을 사용해도 서버에서 계속 처리합니다.
4. 결과 카드를 번갈아 재생해 비교합니다. 하단 플레이어에서 위치·음량을 조절할 수 있고, 페이지를 이동해도 재생이 이어집니다.
5. 하트로 음원을 보관하고 **보관함**에서 여러 프로젝트의 즐겨찾기를 모아 듣습니다. 하트를 해제해도 원본은 프로젝트에 남습니다.
6. 음원 이름을 바꾸거나 **원본 다운로드**로 WAV를 내려받습니다. 이름 변경은 오디오 내용을 바꾸지 않습니다.
7. 과거 프롬프트를 작성칸으로 가져와 새 작업을 만들 수 있습니다. 입력 가져오기는 자동 생성을 하지 않으며, 원래 이력도 유지됩니다.

저장된 프로젝트·생성 이력·즐겨찾기는 앱을 재시작해도 남습니다. 작성 중인 초안은 이 탭 안에서만 임시 보관하며 새로고침하면 사라집니다. 음원 삭제는 그 음원과 원본 파일을 제거하고 생성 이력·프롬프트를 남깁니다. 프로젝트 삭제는 소속 이력·음원을 함께 제거하므로 확인 창의 대상과 범위를 확인합니다.

## 저장 위치와 백업

`SOUNDRY_DATA_DIR`는 데이터 저장 위치입니다. 생략하면 저장소의 `data`를 사용하며 상대 경로도 저장소 기준입니다. 기본 파일은 `data/soundry.db`, `data/audio/`, `data/temp/`에 있습니다. 같은 저장 폴더는 서버 하나만 사용할 수 있습니다.

백업할 때는 작업이 끝나거나 취소된 것을 확인하고 **Ctrl-C로 Soundry 서버를 종료한 뒤, 선택한 data 폴더 전체를 다른 위치에 복사**합니다. DB와 음원을 함께 보관해야 합니다. 복구도 서버가 꺼진 상태에서 수행하고 기존 폴더를 먼저 보존합니다. 백업 폴더를 사용할 때는 `SOUNDRY_DATA_DIR`를 그 폴더로 지정할 수 있습니다.

저장 경로에 symlink가 있으면 시작을 거부합니다. macOS에서 임시 저장소를 직접 지정할 때는 `/private/tmp`처럼 실제 경로를 사용합니다. `.env`와 사용자 DB·음원은 Git에 넣지 않습니다.

## 문제가 생겼을 때

| 화면이나 터미널의 안내 | 해결 방법 |
|---|---|
| CLI를 찾을 수 없음 / 로그인 필요 | Codex CLI 설치와 ChatGPT 로그인을 확인하고 공급자 상태를 다시 확인합니다. Soundry에서 키를 입력하지 않습니다. |
| CLI 사용 한도·연결·출력 검증 오류 | 화면의 설명을 확인하고 문제가 해결된 뒤 직접 새 요청을 제출합니다. 유료 API 전환이나 자동 재시도는 하지 않습니다. |
| 포트가 사용 중 | UI의 5173 충돌이면 `.env`에 `UI_PORT=5174`를 지정하고 5174 주소로 접속합니다. API 3000 충돌이면 사용 중인 서버를 확인해 종료한 뒤 다시 실행합니다. |
| 저장 폴더를 사용하는 서버가 이미 실행 중 | 기존 Soundry를 사용하거나 해당 서버를 Ctrl-C로 종료합니다. 별도 보관소가 필요하면 다른 `SOUNDRY_DATA_DIR`를 지정합니다. |
| 원본 음원 파일을 찾을 수 없거나 변경됨 | 파일이 이동·삭제되었는지 확인합니다. 복구할 백업이 있다면 서버를 종료하고 저장 폴더를 복구합니다. 백업이 없으면 남아 있는 프롬프트로 새 작업을 만들 수 있습니다. |
| 서버 종료로 작업이 중단됨 | 재시작한 앱에서 해당 이력을 확인하고 **입력 확인 후 재시도**를 사용합니다. 중단된 작업은 자동으로 다시 생성하지 않습니다. |
| 접수 결과를 확인하지 못함 | 연결이 끊겨도 작업이 접수됐을 수 있습니다. 서버 연결을 복구한 뒤 **같은 요청으로 접수 확인**을 눌러 원래 요청을 확인합니다. |
| 목록·수정·삭제 결과를 확인하지 못함 | 서버 실행 상태를 확인하고 화면의 **다시 불러오기** 또는 **지금 다시 조회**로 저장 상태를 확인합니다. 응답 유실만으로 성공이나 실패를 단정하지 않습니다. |
| 프로젝트 삭제 시 진행 중인 작업이 있음 | 해당 프로젝트에서 작업을 취소하거나 완료를 기다린 뒤 삭제합니다. |

## 검증

실행 중인 Soundry 서버를 종료한 뒤 저장소 루트에서 실행합니다.

```sh
npm run qa
UI_PORT=5174 npm run qa:smoke
git diff --check
```

`qa`는 lint, strict 타입 검사, 자동 테스트, 두 workspace 빌드, 문서·저장 경계 검사와 Mock WAV 검사를 실행합니다. `qa:smoke`는 임시 데이터 폴더로 개발 서버를 띄워 health, Vite proxy, 포트 충돌과 Ctrl-C 종료를 검사합니다. 사용하려는 UI 포트와 API 3000은 비어 있어야 합니다.

개별 명령은 `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run qa:base`, `npm run qa:audio`입니다. 자동 QA는 실제 AI 작곡·음질이나 모든 브라우저의 동작을 보장하지 않습니다. 브라우저별 확인 결과와 미완료 gate는 [출시 체크리스트](docs/quality/release-checklist.md)에 기록합니다.

## 구조와 공급자 설정

- `frontend/`: Vue 3 · Vite · Tailwind, 프로젝트·작업 공간·보관함·플레이어.
- `backend/`: NestJS · Express, 로컬 API·SQLite/Drizzle·생성 작업·음원 저장과 전송.
- `shared/`: JSON 전송 타입만 공유.
- `harness/`: 개발 서버 실행·검증 도구와 작업 템플릿.
- `docs/`: 설계·계획·QA·리뷰 기록.

`MUSIC_PROVIDER=cli`가 기본입니다. 기존 Codex 로그인을 CLI가 직접 사용하며 앱은 인증 파일을 읽거나 복사하지 않습니다. 음악 프롬프트와 설정만 작곡 요청에 포함합니다. API 키 환경변수를 CLI에 넘기지 않고, Fal이나 다른 유료 음악 API로 전환하지 않습니다. 인증·네트워크·사용 한도·악보 오류는 생성 실패로 표시합니다.

`MUSIC_PROVIDER=mock`을 명시하면 네트워크 없이 자체 제작한 고정 8초 데모를 반환합니다. 이 모드에서는 프롬프트가 음원을 바꾸지 않습니다. 실제 작곡 결과와 구분해 표시합니다. CLI seed는 로컬 음색·미세 연주 변화에 반영되며 동일 프롬프트가 매번 같은 AI 악보를 만든다는 보장은 아닙니다.
